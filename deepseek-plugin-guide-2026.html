01

dsh-market / dsh-market

插件市场 · 生态入口

8.9k

装插件的第一站。它把浏览、搜索、一键安装、更新与卸载搬进 DSH，还提供一个可以接进官方「发现」页的社区索引——新版 DSH 的 Discover 默认是空索引，正好由它补上。先装它，后面所有插件都能在界面里找到，不必再靠收藏夹里的 GitHub 链接。

  • 按名称、功能、分类搜索，卡片直接显示兼容版本
  • 兼容 DSH 实验性的自定义插件市场，可添加社区索引源
  • 顺带管理主题与收藏，减少在浏览器和终端之间来回切
可视化市场一键安装兼容 Discover
dsh plugin --profile web add github:dsh-market/dsh-market

注意社区市场不等于官方认证。DSH 只校验索引格式，不验证标题、来源与安全性；安装前仍要看确认框里的仓库地址。

02

DSH-better-sidebar / omdsh-dev

侧边栏工作台

4.5k

把文件树、CodeMirror 编辑、真实终端、Git diff、子 Agent 状态一起放进右侧边栏。Agent 改完代码，你可以在同一屏里看文件、跑测试、审 diff，不用在编辑器、终端和聊天窗口之间反复横跳。崔添翼曾在 X 上专门推荐过它。

  • 内置文件预览/编辑、终端、Git 面板与子 Agent 页面
  • 开放 ctx.betterSidebar，第三方插件可注册新 Tab
  • 与 dsh-web 可叠加，但功能有重叠，二选一更清爽
文件树内嵌终端Git diff
dsh plugin --profile web add github:omdsh-dev/DSH-better-sidebar

注意插件与宿主版本有对应关系，升级 DSH 后若侧栏白屏，先回滚到匹配版本，而不是反复重装。

03

modlens / liustack

视觉桥 · 外挂眼睛

4.5k

DSH 的第一个视觉插件。DeepSeek 文本模型本身不能看图，modlens 用外部视觉引擎把截图转成可引用的结构化证据：OCR 文本、阅读顺序、版面块、实体与关系。报错截图、UI 设计稿、表格照片，粘进对话就能问。

  • 粘贴即读，输出 JSON 证据而不是一段模糊描述
  • 可复用本机已有的 Claude Code / Codex / OpenCode 视觉通道
  • 同作者的 modsearch 可一起装，补联网搜索
OCR版面分析结构化证据
dsh plugin --profile web add github:liustack/modlens

注意需要自备视觉 API 或本机视觉 CLI，成本取决于提供方；敏感截图会离开本机，机密项目先确认数据流向。

04

dsh-context / bowenliang123

上下文透视与治理

3.6k

长任务跑到一半开始答非所问，通常不是模型变笨，而是上下文被压缩、工具结果挤占了预算。dsh-context 提供面板、浏览器、侧栏和命令，把当前会话的 token 组成、增长曲线、压缩事件、多 Agent 消耗全部摊开。

  • 系统提示、工具结果、历史消息各占多少，一眼看清
  • 跨会话统计与费用估算，知道钱花在哪个环节
  • 支持查看压缩前后发生了什么，便于调整工作流
Token 面板压缩事件成本估算
dsh plugin --profile web add github:bowenliang123/dsh-context

注意它让上下文「可见」，不负责「变少」。真正的瘦身仍要靠拆任务、清工具输出和合理的记忆策略。

05

dsh-web / zhu1090093659

Web UI 全家桶（原 dsh-web-ui）

9.5k

如果只装一个界面插件，就装它。任务看板（含 cron）、Git 图谱、右侧文件/预览/SCM、手机扫码遥控、SSH 远程运维、实时 TPS 与 token 统计、皮肤与桌宠，一次装齐。适合不想逐个挑组件、只想把默认聊天框升级成工作台的人。

  • 看板 + Git 图谱 + 右侧工作区，项目状态不离开页面
  • 手机扫码接管，出门时也能看任务进度
  • SSH 面板适合把 DSH 跑在远程开发机上
任务看板Git 图谱移动端遥控
dsh plugin --profile web add github:zhu1090093659/dsh-web

注意全家桶已整合 better-sidebar。装它之后不必再单独装侧边栏，否则可能出现重复 Tab 或样式冲突。

06

dsh-TUI / ccch1mneyyy

终端界面 · 键盘流

5.8k

Claude Code 风格的全屏终端：像素鲸鱼顶栏、流式展开的思考、双击 Esc 回滚、上下文进度条、TPS 仪表。SSH 到没有图形界面的服务器时，它比开端口转发再开浏览器靠谱得多。官方公众号曾把它作为内测精选插件介绍。

  • 纯键盘操作，切会话、换模型、回滚都不用鼠标
  • 低占用，适合长期挂在 tmux / SSH 会话里
  • 与 Web UI 并存，不要求你放弃图形界面
全屏 TUISSH 友好回滚 / 分支
dsh plugin add github:ccch1mneyyy/dsh-TUI

注意它使用自己的 profile，不要装进 web。安装前先确认仓库写明的宿主版本，TUI 对版本变化比 UI 插件更敏感。

07

dsh-desktop / anywhere-labs

社区桌面客户端

33.1k

桌面客户端里星标最高的项目。把 DSH 包成原生桌面应用：独立窗口、系统托盘常驻、终端集成、插件管理，告别「浏览器标签页被误关，任务全断」。它自己也按插件架构组织，桌面壳只是最外层。

  • 独立窗口 + 托盘，长任务在后台跑更安心
  • 内置插件管理，适合完全不想碰命令行的用户
  • 可组合的桌面壳，后续能替换界面层
桌面客户端托盘常驻独立发行版
这是独立客户端，不是 web profile 插件。按仓库 README 下载安装包；官方目前也提供桌面版，二选一即可。 打开仓库 →

注意兼容性取决于客户端内置的 DSH runtime 版本。宿主升级后，插件可能要先等客户端跟进。

08

dsh-mnemon / omdsh-dev

分层记忆 · 跨会话

— 未统计

给 DSH 一套「分层、可见、可组合」的记忆：偏好与工作事实常驻上下文，项目文档按需检索，长期记忆放进可切换的 Memory Space。每条回复下方会列出本轮读了什么、写了什么，点一下就能打开原文，不用猜 Agent 记住了什么。

  • 运行时记忆 / 项目文档 / 记忆空间三层，按需加载
  • 后端可换：本地 Mnemon Native、OpenViking、Mem0、Supermemory 等
  • 附带 Skills 管理：版本、回测、按真实对话进化（默认关闭）
分层记忆可追溯多后端
dsh plugin --profile web add dsh-mnemon

注意插件是进程内 JavaScript，不是沙箱。记忆文件与备份可能含密钥、客户信息，务必控制目录权限并加密备份。

09

dsh-browser / Lum1104

真实浏览器控制

— 未统计

接你正在用的 Chrome / Firefox，保留登录态、Cookie 和会话。页面被转成带编号的文本控件清单，模型按编号点击、输入、导航，而不是靠截图猜坐标。密码与卡号永远渲染成 ••••，点击与输入默认逐次审批。

  • 用真实浏览器，不另开无头副本，登录态不丢
  • 文本优先的页面接口，比截图方案少一轮视觉推理
  • 受保护页面（扩展商店、部分支付页）只读元数据，不碰 DOM
Chrome / Firefox登录态保留逐次审批
不能用 dsh plugin 直接装：需要跑仓库的安装脚本，再在浏览器里加载扩展并重启 DSH。 看安装说明 →

注意npm 上同名的 dsh-browser 属于另一个项目，与它无关。认 owner，不认名字。

10

dsh-vision-toolkit / Anionex

进阶视觉工具箱

0.9k

比 modlens 更重的前端/设计向视觉工具：长截图 OCR、UI 还原、像素级定位与对比、可预览的 Artifacts。十个工具按需暴露，避免一次把整套视觉 schema 塞进上下文。适合拿设计稿还原页面、做视觉回归的人。

  • 长截图分段识别，适合聊天记录、整页文档
  • Grounding 与像素对比，能定位「差了几个像素」
  • 工具按需加载，不用时不吃上下文预算
UI 还原像素对比长截图 OCR
dsh plugin --profile web add github:Anionex/dsh-vision-toolkit

注意和 modlens 功能重叠。先装 modlens 试水，确实需要像素级还原再换它，别两个一起开。

Composio / composio.dev

1,500+ SaaS 集成

— 商业服务

让 Agent 不只活在代码目录里。通过一个 CLI 接入 GitHub、Slack、Gmail、Linear、Calendar 等 1,500+ 应用，OAuth、API Key、scope、token 刷新都由它托管，不用为每个 SaaS 单独写一个插件。

  • 一个集成层替代十几个碎片化插件
  • 托管认证与凭据刷新，省掉最容易出事的一环
  • 用 shell 就能调用，不强制额外配 MCP server
SaaS 集成OAuth 托管CLI
composio login

注意商业服务，数据会经过其云端。先用免费额度跑通一条只读流程，再决定是否接生产账号。

OpenViking / volcengine

团队级记忆与知识库

40.8k

火山引擎开源的 Agent 上下文数据库：统一记忆、知识 RAG 与 Skills 管理，并提供 DSH 记忆插件。它解决的不是「记住我的偏好」，而是「整个团队的知识如何被 Agent 检索和复用」。星标很高，但接入门槛也最高。

  • 记忆、知识库、技能统一到一个上下文层
  • 适合已有文档资产、要做团队级 RAG 的场景
  • 可作为 dsh-mnemon 的 Memory Space 后端之一
团队知识库RAG需自建服务
先部署或接入 OpenViking 服务，再按插件文档配置。只记几条偏好的人，用 dsh-mnemon 就够了。 打开仓库 →

注意它是平台，不是「装完即用」的小插件。没有运维预算时，别把它当记忆插件的默认选项。

Recipes

别全装。按你的工作流选一套

插件之间会抢界面、抢上下文、抢快捷键。下面三套组合经过取舍，每一套都只保留必要的重叠。

Recipe 01 · 轻量起步

先把体验拉直

适合第一次用 DSH、只想解决「找插件、少切窗口、能看图」的人。15 分钟，三次重启。

  1. dsh-market先有市场，后面都在界面里装
  2. DSH-better-sidebar文件、终端、Git 一步到位
  3. modlens截图能看懂，排错效率翻倍
预期结果：不切窗口完成「改代码 → 跑测试 → 看截图」
Recipe 02 · 长任务工作台

让任务不断片

适合一个任务跑几十分钟、经常被上下文压缩打断的人。重点是「看得见 + 记得住」。

  1. dsh-context先知道上下文花在哪
  2. dsh-mnemon跨会话记住决策与偏好
  3. dsh-web看板管任务，Git 图谱看改动
预期结果：新会话不用重讲背景，压缩后能接着干
Recipe 03 · 终端与外部世界

SSH 里也能干活

适合远程开发、需要 Agent 碰浏览器和 SaaS 的人。图形界面不是必需品。

  1. dsh-TUI纯键盘，低占用，挂 tmux 里
  2. dsh-browser真实登录态，点页面不用截图
  3. Composio把 PR、Issue、消息接进来
预期结果：一台服务器 + 一个终端，完成查资料到提 PR

Install & verify

装完必须重启，刷新页面不算

DSH 的插件装在 profile 里。命令把包写进 profile 的组合配置，宿主进程启动时才挂载；只刷新浏览器，新插件不会出现。

官方命令dsh plugin --profile <name> add
PowerShell / bash
# 1. 确认 DSH 可用
dsh --version

# 2. 从 GitHub 装（最通用）
dsh plugin --profile web add github:owner/repo

# 3. 从 npm 装（有明确包名时）
dsh plugin --profile web add dsh-mnemon

# 4. 固定 commit，避免上游改坏
dsh plugin --profile web add github:owner/repo#3f9c2e1

# 5. 检查是否进了组合配置
dsh --profile web --dump-config

# 6. 重启宿主（不是刷新页面）
dsh web
1
先认 profile

Web UI 用 web，TUI 和 headless 各有自己的 profile。装错 profile，表现就是「命令成功但界面没变化」。

2
看包有没有 dsh.bundle

没有 bundle 声明的包只会作为普通依赖安装，不会激活任何一层。装完没反应，先查这里。

3
Git 安装会执行构建脚本

来自 GitHub 的包可能在安装时跑代码。固定 commit、读一遍 package.json 的 scripts，再决定是否放行。

4
用官方「发现」页接管索引

设置里打开实验性「自定义插件市场」，添加可信索引 URL；http 索引可被中间人篡改，务必用 https。

症状最可能的原因处理
装完毫无变化包未声明 dsh.bundle，或装错了 profile查 package.json；确认 --profile web；重启宿主
页面白屏 / 控制台报错插件与宿主版本不匹配回滚插件版本。DSH 仍是 developer preview，破坏性变更很正常
设置保存失败手动把 cordis.patch.yml 的 insert 复制进 profile，出现重复条目删掉重复项，让 DSH 自动加载 bundle（mnemon 文档明确警告过）
技能或部分插件不生效启动时未应用 patch试 dsh web --patch。这是社区经验，随版本可能变化
dsh-browser 连不上只装了包，没装浏览器扩展与桥用仓库安装脚本，加载扩展，重启 DSH；检查 /ext/bridge-config

Trust boundary

插件不是主题包，它跑在你的进程里

它能读 API Key、会话日志、工作区文件，也能在本机开端口。DSH 官方明确说：插件是第三方内容，格式会被校验，但声明不会被验证。下面三条不是建议，是底线。

01只装声明了 bundle 的包

没有 dsh.bundle 的仓库，要么还没做完，要么根本不是 DSH 插件。前者等，后者别装。

02固定 commit，不追 latest

开发者预览期，上游一次重构就可能让插件拿到你的凭据。写死 SHA，升级前先看 diff。

03装前读两个文件

看 cordis.patch.yml 注入了什么，看工具清单能碰什么。读不懂就先别装。

特别警惕「免登录、免 Key、不限量」的模型插件

一个星标四万的插件声称不登录就能白嫖前沿模型。这类项目的成本一定由别处承担：你的数据、你的机器，或者它随时可能断供。生产机上不要装。

npm 同名抢注已经发生了

dsh-browser 的 README 专门声明：npm 上未加 scope 的 dsh-browser 属于另一个项目，与本仓库无关。安装时认 owner 和仓库地址，不要只认包名。

dsh-plugin-check · 只读体检清单协议与构建陷阱 dsh-security-audit · 配置 / 凭据 / 插件来源 / 暴露面 两者都给报告，不改仓库

Method & sources

这份榜单是怎么来的

先用 AnySearch 做广度检索，再回到官方文档与仓库逐条核对。星标只是热度，不是推荐理由。

检索覆盖中英文十余组关键词，分别对应「推荐 / 榜单 / 安装 / 安全」四类意图；候选池来自 GitHub dsh-plugin 话题、社区精选列表与媒体盘点，再用官方文档确认安装方式与版本约束。

  • 排序维度：通用性（是否多数人用得上）× 不可替代性（是否只能靠它解决）× 维护活跃度（近期提交与版本跟进）。
  • 星标口径：取 2026-10-25 的社区星标目录快照，四舍五入到 0.1k；标注「—」表示该目录未收录，或该条目不是 GitHub 仓库。
  • 排除范围：VSCode 套壳、浏览器侧边栏扩展、纯 API 客户端不进入主榜；客户端、平台与集成层单独标注，避免混为一谈。
  • 利益披露：本文不含任何推广或返佣；安装命令按官方 dsh plugin 语法与各仓库 README 整理。

插件生态仍在快速变化。安装前请以仓库当日 README 为准；若本文与仓库冲突，信仓库。
