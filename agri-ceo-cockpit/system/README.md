# 农资经营系统 · 最小可用闭环（MVP）

这不是原型截图，是一条**真正跑得通的数据链路**：

```
周报填报（UI 表单 / API）
      ↓  写入
SQLite 数据库（420 条周度事实，幂等 upsert + 审计日志）
      ↓  聚合
指标层（收入 / 毛利率 / 回款率 / 周转 / 达成率 / 履约率）
      ↓  规则
建议引擎（P0/P1/P2，带事实、动作、影响金额）
      ↓
前端实时刷新（KPI + 图表 + 建议 + 填报记录）
```

改一条周报数据 → 保存 → 所有指标、图表、建议立刻重算。这就是"系统"和"看板"的区别。

---

## 快速开始

```bash
cd system
python server.py
# 浏览器打开 http://127.0.0.1:8787
```

- 无需安装任何第三方库（Python 3.8+ 标准库 + 内置 SQLite）
- 首次启动自动建表并生成 420 条演示数据（`data.db`）
- 端口被占用可改：`set PORT=8899 && python server.py`（PowerShell：`$env:PORT=8899`）
- 接口自测：`python test_api.py`（会写入再还原一条记录，验证"写入→重算→建议变化"）

## 怎么验证"真的会重算"

1. 打开页面，记住顶部「回款率」和右侧「系统建议」条数
2. 在下方「周报填报记录」里点任意一行的 **编辑**
3. 把 **回款率** 改成 `45`、**库存周转** 改成 `120`，备注写"压力测试"
4. 点 **保存并重算**
5. 观察：KPI 变化、建议里出现新的 P0 条目、右上角更新时间刷新

删除一条记录同理，指标会立即回退。

## 页面结构

| 区域 | 内容 | 交互 |
|---|---|---|
| 顶部 | 连接状态、最后更新时间 | 刷新 |
| 筛选 | 大区（全国/7 大区）、周期（本周/近 4 周/全周期） | 全部指标联动 |
| KPI | 收入、毛利率、回款率、周转、达成率、履约率 | 同比颜色 + 目标提示 |
| 周度营收与毛利 | 12 周柱状 + 目标虚线 + 毛利折线 | hover 看数值 |
| 系统建议 | 规则引擎输出（≤6 条） | 事实 / 动作 / 影响金额 |
| 品类结构 | 收入占比 + 毛利率 | — |
| 大区完成率 | 相对 100% 的缺口/超额发散条 | 回款率红色告警 |
| 周报填报记录 | 最近 60 条 | 编辑 / 删除 / 新增 |

## API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/health` | 健康检查 |
| GET | `/api/meta` | 下拉选项（大区、品类、周次） |
| GET | `/api/state?region=&period=` | 全部看板数据（KPI/序列/品类/大区/建议/记录） |
| POST | `/api/weekly` | 新增或覆盖（幂等，键 = 周次 + 大区 + 品类） |
| DELETE | `/api/weekly/{id}` | 删除一条 |

`period` 取值：`周` / `4周` / `年`。

示例：

```bash
curl "http://127.0.0.1:8787/api/state?region=%E5%85%A8%E5%9B%BD&period=4%E5%91%A8"
```

## 数据模型

```sql
weekly(
  id, week, region, category,
  revenue,          -- 销售收入（万元）
  target,           -- 目标（万元）
  gross_margin,     -- 毛利率 %
  collect_rate,     -- 回款率 %
  inventory_days,   -- 库存周转天数
  receivable,       -- 应收余额（万元）
  expiring,         -- 临期金额（万元）
  orders, fill_rate,-- 订单数、履约率
  owner, note, updated_at,
  UNIQUE(week, region, category)   -- 幂等键，重复提交即覆盖
)
audit(id, ts, action, payload)     -- 谁在什么时候改了什么
```

## 建议引擎（当前 6 条规则）

| 触发条件 | 级别 | 输出 |
|---|---|---|
| 目标达成率 < 95% | P0 | 缺口金额 + 拆解动作 |
| 回款率 < 88% | P0 | 风险敞口 + 停货/提成建议 |
| 收入环比 < -7% | P0 | 下滑幅度 + 拖累大区 |
| 库存周转 > 60 天 | P1 | 可释放资金 + 清库动作 |
| 单一大区回款率 < 82% | P1 | 大区 + 额度调整 |
| 临期率 > 3% | P1 | 跌价损失 + 调拨建议 |
| 高毛利品类占比可提升 | P2 | 结构优化收益 |

> 规则可配置化（阈值、动作、责任人进数据库）是下一步，见《../系统化升级方案.md》第 6 节。

## 这个 MVP 没做什么（生产化清单）

- [ ] 登录 / 角色 / 数据行级权限
- [ ] 审批流（提交 → 大区审 → 财务复核）
- [ ] Excel 批量导入与校验预览
- [ ] 与 ERP / 进销存 / 经销商 APP 的接口对接
- [ ] 指标层的物化视图与增量调度（现在是请求即算，数据量大要改）
- [ ] 建议的派单、跟踪、闭环（现在只展示）
- [ ] 移动端（企微 / 小程序）
- [ ] 部署（Nginx + Gunicorn/Uvicorn + PostgreSQL）、备份、监控

每一项的工时与顺序见《系统化升级方案.md》第 10 节。

## 技术说明

- 单文件后端 `server.py`：`ThreadingHTTPServer` + `sqlite3`，请求级连接
- 聚合用 Python 完成（MVP 规模 420 行足够）；生产建议下推 SQL 或建 DWS 宽表
- 金额统一「万元」，比率统一「%」，避免前后端换算歧义
