# 从零搭建这套系统：学习与执行路线图

> 适用前提：你已经看过原型（[index.html](index.html)）和可运行的最小闭环（[system/README.md](system/README.md)）。
> 这份文档回答两个问题：**学什么、按什么顺序学**；**做到哪一步该自己写、哪一步该找人**。

---

## 0. 先定位：你是哪一种"从零开始"

同一份系统，三种人的学法完全不同。先花 10 分钟做三个自测：

| 自测问题 | 是 → | 否 → |
|---|---|---|
| 你能读懂 `if / for / 函数` 这类代码吗？ | 有编程底子 | 纯业务背景 |
| 你打算亲手写代码，还是指挥别人写？ | 技术路线 | 业务路线 |
| 你的目标是"3 个月上线一个能用的"，还是"半年内自己掌握这门手艺"？ | 速成 | 长线 |

三种典型角色：

| 角色 | 你要学到什么程度 | 时间 | 产出 |
|---|---|---|---|
| **A. 业务负责人**（不写代码，负责提需求、验收） | 能读懂数据流、能定指标口径、能判断页面真假 | 2-3 周 | 需求文档 + 指标字典 + 验收清单 |
| **B. 技术负责人**（带 1-2 个人做） | 架构、后端、数据库、前端都要懂，能 review | 3-4 个月 | 可上线的系统 |
| **C. 独立开发者**（一个人做出来） | 全栈 + 部署 + 运维，且必须砍范围 | 6-10 个月 | 单大区可用的 MVP |

> **我的建议**：如果你不是程序员，**不要从"学编程"开始**，而是走 A 路线——先把口径和验收定死，再找 1 个后端 + 1 个前端执行。你省下的不是时间，是返工。

## 1. 为什么学习顺序必须是"业务 → 数据 → 后端 → 前端"

绝大多数人从"学 Vue / 学 Python"开始，结果做了三个月做不出能用的东西。原因是：**驾驶舱的难点从来不是技术，是"这个数到底怎么算"**。

倒推逻辑：

```
你要交付的是"每周数据进来 → 指标对 → 建议有用"
        ↑ 靠指标口径（业务）
        ↑ 靠表结构和聚合（数据）
        ↑ 靠接口（后端）
        ↑ 靠页面（前端，最不重要）
```

所以顺序是：**口径 → 数据 → 接口 → 页面**。反过来做，前面全白干。

```
能力栈（自下而上，也是学习顺序）

    ┌─────────────────────┐
 4  │ 前端：Vue + ECharts  │  会调接口、会画图、会处理空/错/加载态
    ├─────────────────────┤
 3  │ 后端：FastAPI + SQL  │  会写增删改查、会校验、会鉴权、会定时
    ├─────────────────────┤
 2  │ 数据：PostgreSQL     │  会建表、会 JOIN、会 GROUP BY、会窗口函数
    ├─────────────────────┤
 1  │ 业务：指标与口径      │  说得出每个数字从哪来、怎么算、谁负责
    └─────────────────────┘
```

## 2. 四层学习地图（含验收作业）

### 第 1 层：业务与指标（3-5 天）

**学什么**

- 农资业务流：订单 → 发货 → 回款 → 返利 → 退换货，每一步产生什么数据
- 12 个核心指标的口径：收入、毛利率、回款率、账龄、库存周转、临期率、达成率、履约率、动销率、经销商健康分、单吨费用、客户复购率
- 期间与单位：周/月/季/年，含税/不含税，万元/元（**全公司只能有一套**）

**怎么学**

- 把公司 ERP 里最近 3 个月的销售、回款、库存报表各导一份，自己用 Excel 复算一遍
- 找财务要一次"月结口径说明"，问清楚：退货怎么冲、返利怎么计提、运费进不进成本
- 读《数据化管理》（黄成明）前 3 章，建立"指标—业务动作"的对应感

**验收作业（不做完不要往下走）**

手写一张指标字典，至少 10 行，每行包含：

| 指标 | 公式 | 数据源 | 更新频率 | 责任人 | 异常阈值 |
|---|---|---|---|---|---|
| 回款率 | 本期回款 / 本期应收发生额 | 资金系统 | T+1 | 财务 | < 88% 预警 |
| 库存周转 | 平均库存成本 / 日均出库成本 | WMS | 实时 | 供应链 | > 60 天预警 |
| … | | | | | |

这张表后面会变成系统里的 `metric_dict` 表——**它是整个项目的地基**。

---

### 第 2 层：数据与 SQL（2-3 周）

**学什么**

- 关系模型：主键、外键、一对多、为什么主数据要单独建表
- SQL 四件套：`SELECT / JOIN / GROUP BY / 窗口函数`
- 索引与执行计划（知道 `WHERE` 没走索引会慢就行）
- 事务与幂等（`UNIQUE` 约束怎么做"重复提交只留一条"）

**怎么学**

- 交互式过一遍 [SQLBolt](https://sqlbolt.com/)（半天）
- 跟着 [PostgreSQL 官方教程](https://www.postgresql.org/docs/current/tutorial.html) 把 `system/data.db` 导进 PostgreSQL 练手
- 装 DBeaver 或 Navicat，用图形界面看表结构

**验收作业**

不写一行 Python，只用 SQL 回答：

1. 每个大区最近 4 周的收入、毛利率（加权）
2. 每个品类本周收入占全国比重，以及与上周的差
3. 回款率低于 85% 的大区及其应收余额
4. 用窗口函数算出每个大区收入的周环比

> 能写出这 4 条，你就具备了和开发对话的资格。

---

### 第 3 层：后端 API（3-4 周）

**学什么**

- Python 基础（若零基础，先花 2 周）：变量、列表/字典、函数、类、异常、文件、虚拟环境
- HTTP 与 REST：方法、状态码、JSON、幂等
- FastAPI：路由、Pydantic 校验、依赖注入、Swagger 自动文档
- 数据库访问：SQLAlchemy 或 psycopg，事务
- 鉴权：JWT + 角色；行级权限（按 `region_id` 过滤）
- 定时任务：APScheduler 做每日/每周重算

**怎么学**

- [FastAPI 中文文档](https://fastapi.tiangolo.com/zh/) 的 Tutorial 部分，从头到尾敲一遍（这是目前最好的入门材料）
- 把 `system/server.py` 的 stdlib 版本**改写成 FastAPI**：接口路径不变，加自动文档
- 读《SQL 必知必会》（Ben Forta）补 SQL 细节

**验收作业**

- 三个接口：`GET /api/state`、`POST /api/weekly`、`DELETE /api/weekly/{id}`
- 打开 `/docs` 能直接调通
- 参数校验失败返回 422 且信息可读
- 数据库从 SQLite 换成 PostgreSQL，数据迁移脚本可重复执行

---

### 第 4 层：前端可视化（3 周）

**学什么**

- HTML / CSS / JS 基础：盒子模型、flex/grid、`fetch`、`async/await`、事件
- 框架二选一：**Vue 3**（中文文档好、上手快）或 React
- 图表：[ECharts](https://echarts.apache.org/zh/index.html)，先抄示例再改
- 三态处理：加载中 / 空数据 / 请求失败（**这是业余和专业的分水岭**）

**怎么学**

- [Vue 3 中文文档](https://cn.vuejs.org/) 的"基础 + 组件"两章
- 把 `system/web/index.html` 用 Vue 重写——现有页面就是最好的设计稿
- ECharts 官网示例，先把柱状 + 折线组合图跑通

**验收作业**

- 6 个 tab 全部动态化，数据只来自 API，HTML 里没有一个硬编码数字
- 切换大区/周期时不再整页刷新
- 接口挂掉时页面显示"加载失败，重试"，而不是白屏

---

### 第 5 层：工程化与上线（1-2 周）

| 内容 | 学到什么程度 |
|---|---|
| Git | add/commit/push/branch/回滚 |
| Docker | 会写 Dockerfile 和 docker-compose 起前后端 + 数据库 |
| Nginx | 会配反向代理和 HTTPS |
| 备份 | PostgreSQL 每日 `pg_dump` + 异地留存 7 天 |
| 监控 | Uptime Kuma 或云监控，接口挂了能收到通知 |

**验收**：一台 2 核 4G 云服务器，域名可访问，重启后自动恢复，数据库每天自动备份。

## 3. 两条执行路线

### 路线 A：你主导，找人做（推荐给业务背景的人）

| 阶段 | 你负责 | 别人负责 | 时间 |
|---|---|---|---|
| M0 立项 | 指标字典、验收标准、试点大区 | — | 1 周 |
| M1 数据可用 | 协调 ERP/财务导数据 | 建库、导数、清洗 | 2 周 |
| M2 闭环演示 | 验收"改数即变" | 后端 + 前端最小闭环 | 2 周 |
| M3 试点 | 组织使用、收集反馈 | 迭代 4 个模块 | 4 周 |
| M4 全量 | 推广、考核 | 权限、移动端、ERP 对接 | 4-6 周 |

**你要盯的三件事**：口径不许改、填报不超过 3 分钟、每条建议必须有人认领。

### 路线 B：你自己写

**范围必须砍**：只做一个大区、只做 4 个模块（总览/销售/渠道/资金）、只做 PC 端、不接 ERP（先手工填报）。

按第 2 节的顺序推进，**每周产出一个能跑的东西**，不要连续两周只看书。

## 6. 什么时候该停止自学、开始雇人

三个明确信号，出现任意两个就该找人：

1. **你能画出完整数据流图、说清每个指标口径** → 你已经具备"指挥"的能力，不必再学写代码
2. **改一个需求要花你超过 1 天** → 你的时间成本已经高于外包
3. **系统要接 ERP、做行级权限、上生产环境** → 这是专业工程问题，不是学两周能解决的

反过来，**这几种情况不要雇人**：还没定指标口径、还没确认高管会每天用、还想不清楚要哪 4 个模块。

## 7. 第一个 30 天怎么过（可直接照做）

| 时间 | 做什么 | 交付物 |
|---|---|---|
| D1-D2 | 装环境：Python、VS Code、Git、DBeaver | 能跑 `python server.py` |
| D3-D5 | 读 `system/server.py`，画出数据流图（输入→存储→计算→输出） | 一张手绘图 |
| D6-D7 | 用 SQL 复算 3 个指标，和页面数字对上 | 对得上的证据 |
| D8-D14 | 指标字典第一版（10 个指标），找财务确认 | 签字版表格 |
| D15-D21 | 动手改 3 个地方：加一个指标、加一个接口、加一张图 | 可运行的新版本 |
| D22-D30 | 数据库换 PostgreSQL，写迁移脚本，重跑一遍 | 迁移成功的日志 |

> 这 30 天做完，你会比 90% 的"想做个系统"的人更清楚自己要什么。

## 附：常见误区

| 误区 | 后果 | 正确做法 |
|---|---|---|
| 先学框架再想业务 | 做出来的东西没人用 | 先定 10 个指标 |
| 一开始就上微服务/中台 | 三个月搭不出一个页面 | 单体 + 一个数据库 |
| 追求"实时" | 拿到错的实时数 | 分级：交易实时、财务 T+1 |
| 让业务员填 40 个字段 | 三个月后数据全假 | 只填系统拿不到的 5 个 |
| 建议写死在代码里 | 阈值一变就要发版 | 规则入表，后台可配 |
| 不做权限 | 大区总看到隔壁客户 | 第一版就做行级权限 |
