# 8 周练手计划：把现有 MVP 改造成你自己的系统

> 用法：不要另起炉灶。就在 [system/](system/README.md) 这份能跑的代码上改，**每周交付一个能打开、能操作的版本**。
> 每周投入约 15-20 小时（工作日 2 小时 + 周末 6 小时）。只有 5 小时/周的话，把 8 周拉成 16 周，顺序不变。

---

## 为什么要"改"而不是"从零写"

从零写一个新项目，你会同时面对：需求不清、框架不会、报错不懂、没有参照物——四重打击，多数人第二周就放弃。

而在一个**已经跑通**的 400 行后端 + 500 行前端上改，你每次只需要解决一个问题，且立刻能看到效果。这是学编程最有效的姿势：**小步、可运行、有反馈**。

---

## 每周固定节奏

| 时间 | 做什么 |
|---|---|
| 周一（1h） | 读本周要改的代码，画出改动点，写下"我预期它会怎么变" |
| 周二—周四（各 1.5h） | 写代码，每完成一小步就重启验证 |
| 周五（1h） | 验收 + 写 5 行日志（改了什么、卡在哪、怎么解决的） |
| 周末（6h） | 补齐没做完的部分 + 读一点原理 |

> 日志比代码重要。8 周后你回看，会发现 80% 的时间浪费在重复踩同一个坑。

---

## 第 1 周：跑通它，并说清数据从哪来

**目标**：不写新功能，先建立"我能掌控它"的信心。

**动手**

1. 启动服务，打开 `http://127.0.0.1:8787`，把每个按钮都点一遍（筛选、编辑、删除、新增）
2. 浏览器 F12 → Network，刷新页面，看 `/api/state` 返回的 JSON，找到 `kpis` 里"回款率"这个字段
3. 打开 [server.py:86](system/server.py#L86) 的 `seed()`，把 `CAT_PCT` 里"农药"从 22 改成 30，删掉 `data.db`，重启
4. 观察"品类结构"的变化——你刚刚修改了系统的初始数据

**验收**：手绘一张数据流图，标出 5 个环节：表单 → `weekly` 表 → `agg()` → `advise()` → `/api/state` → 页面。每个环节写一句"它负责什么"。

**你会卡在**：端口被占用（改 `PORT`）、文件编码（用 UTF-8 保存）。

---

## 第 2 周：把 SQLite 换成 PostgreSQL

**目标**：理解"数据库是可以换的，SQL 才是核心"。

**动手**

1. Docker 起一个 PG：`docker run -d -p 5432:5432 -e POSTGRES_PASSWORD=dev postgres:16`
2. 写 `migrate.py`：从 `data.db` 读出 420 行，写进 PG 的 `weekly` 表
3. 改 [server.py:46](system/server.py#L46) 的 `db()`，用 `psycopg` 连 PG；把 `?` 占位符改成 `%s`
4. 类型对照：`REAL → NUMERIC(14,2)`、`TEXT → VARCHAR(32)`、`INTEGER PRIMARY KEY AUTOINCREMENT → BIGSERIAL`

**验收**：页面数字与迁移前**完全一致**——收入 `6376.4`、回款率 `83.4`、建议 5 条。差一位都不算过。

**你会卡在**：连接串格式、时区、`ON CONFLICT` 语法（PG 和 SQLite 写法不同）、中文排序规则。

---

## 第 3 周：后端换成 FastAPI

**目标**：从"手写 HTTP 处理器"升级到"声明式接口"，并拿到自动文档。

**动手**

1. `pip install fastapi uvicorn`，新建 `api/main.py`
2. 把 [build_state()](system/server.py#L247) 原样搬过去（**先别重写逻辑，只换外壳**）
3. 定义 Pydantic 模型 `WeeklyIn`，字段与表单一一对应，加上 `ge=0` 之类的约束
4. 三个接口：`GET /api/state`、`POST /api/weekly`、`DELETE /api/weekly/{id}`
5. 前端把请求地址从 `8787` 改成 `8000`

**验收**：打开 `http://127.0.0.1:8000/docs`，能直接在页面上调通三个接口；传 `collect_rate=200` 会被拦下并给出可读的错误。

**你会卡在**：CORS（前端 5173 / 后端 8000 跨域）、`async def` 与同步数据库调用的混用、依赖注入看不懂（先照抄）。

---

## 第 4 周：登录、角色、行级权限

**目标**：让"谁能看什么"变成代码，而不是靠自觉。

**动手**

1. 建 `users` 表：`id, name, role, region_id, password_hash`
2. `POST /api/login` 校验密码，签发 JWT（`python-jose` 或 `pyjwt`）
3. 写一个依赖 `get_current_user`，从 Header 里解 token
4. **关键**：在 `build_state()` 里按 `user.region_id` 强制过滤——大区角色即使传 `region=全国` 也只能拿到自己大区的数据
5. 写一条审计：每次写操作记 `who / when / what`

**验收**：建两个账号（华东、西北），分别登录。华东账号无论怎么改 URL 参数，都看不到西北的数字。

**你会卡在**：把权限写在前端（大错）、token 存在 localStorage 的 XSS 风险、密码明文入库（必须哈希）。

---

## 第 5 周：前端改成 Vue

**目标**：从"拼字符串"升级到"数据驱动视图"。

**动手**

1. `npm create vite@latest web -- --template vue`
2. 拆四个组件：`KpiCard`、`TrendChart`、`TipsPanel`、`FilterBar`
3. 把 [renderKPI()](system/web/index.html#L289) 的字符串拼接改成模板 + `v-for`
4. 把 [chart()](system/web/index.html#L256) 的 SVG 拼装换成 ECharts（`echarts.init` + `setOption`），注意组件销毁时 `dispose`
5. 加三态：`loading` / `error` / `empty`

**验收**：整个页面 HTML 里**没有一个硬编码数字**；切换大区时页面不闪白；断网时显示"加载失败，重试"。

**你会卡在**：ECharts 容器宽高为 0（要等 DOM 渲染）、`resize` 监听、Vue 的响应式对数组/对象的新增属性不生效。

---

## 第 6 周：加一个完整业务模块（经销商健康度）

**目标**：走一遍"新需求 → 新表 → 新接口 → 新图"的完整链路。这是最重要的能力。

**动手**

1. 建表 `dim_dealer`（经销商主数据）和 `fact_dealer_weekly`（进货、动销、库存、窜货次数）
2. 后端算 DHI：`回款率×40% + 动销率×25% + 库存健康×20% + 合规×15%`
3. 新接口 `GET /api/dealers?region=`，返回分数与四象限分组
4. 前端画四象限散点图（x=同比增速，y=回款率，气泡=采购额）

**验收**：能按 DHI 排序、能点某个经销商看明细、能在图上区分"明星/增长但欠款/压货/危险"四类。

**你会卡在**：散点图的坐标系与气泡大小映射、后端聚合的 SQL 变复杂（用子查询或 CTE）。

---

## 第 7 周：规则引擎配置化

**目标**：改阈值不用改代码——这是"产品"和"作业"的区别。

**动手**

1. 建 `rule` 表：`code, name, level, metric, operator, threshold, action_tpl, impact_formula, enabled`
2. 把 [advise()](system/server.py#L168) 里写死的 if 改成"读规则 → 取指标 → 比较 → 渲染模板"
3. 做一个简单的规则管理页（列表 + 开关 + 改阈值）
4. **不要**把条件存成 `eval()` 的字符串（安全漏洞），用字段 + 运算符表达

**验收**：不改一行代码，把回款率阈值从 88 改成 90，保存后刷新页面，建议列表立刻多一条。

**你会卡在**：阈值改了但缓存没失效（记得清缓存）、影响金额的公式怎么参数化。

---

## 第 8 周：部署上线

**目标**：让别人能用手机打开它。

**动手**

1. 三个 Dockerfile：`api`、`web`（构建成静态文件）、`postgres`
2. `docker-compose.yml` 串起来，Nginx 做反向代理
3. 域名 + HTTPS（Let's Encrypt）
4. `pg_dump` 每日备份到对象存储，保留 7 天
5. Uptime Kuma 监控 `/api/health`，挂了发微信/邮件

**验收**：手机关掉 WiFi 用 4G 能打开；`docker compose down` 再 `up` 数据还在；把备份文件恢复到新库能跑起来。

**你会卡在**：Nginx 的路径转发、前端打包后接口地址写死、容器时区（日期差 8 小时）。

## 结业标准（能独立接活了）

- [ ] 给你一个新指标，你能在 **2 小时内**从建表到出图全链路加完
- [ ] 给你一个新角色，你能说清"他能看哪些行、能改哪些字段"
- [ ] 系统报错时，你先看日志定位，而不是直接重启
- [ ] 你能向非技术同事解释：为什么这个数字是这样算的

## 如果中途卡住超过 3 小时

1. 先把报错原文贴进搜索引擎（不要只贴"报错了"）
2. 把问题缩小到 10 行以内能复现
3. 用 `git stash` 回到上一个能跑的版本，重来
4. 还不行就去问人——**带着"我试过什么、报什么错、我猜是什么原因"去问**，这是最省时间的问法

> 记住：卡住不是能力问题，是信息不足。绝大多数问题，官方文档第一页就有答案。
